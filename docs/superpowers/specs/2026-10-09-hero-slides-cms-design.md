# Hero slides — δυναμική διαχείριση (σχέδιο)

**Ημερομηνία:** 2026-10-09 · **Κατάσταση:** εγκρίθηκε από τον χρήστη

## Πρόβλημα

Τα slides του hero της αρχικής είναι σταθερά στον κώδικα (`heroSlides` στο `lib/data/catalog.ts`). Δεν αλλάζουν χωρίς
deploy, έμειναν με «Καλοκαίρι 2026» / «Σεπτέμβριος», και η ζώνη του hero είχε λήξη 30/9 — από 1/10 η αρχική έμεινε χωρίς
hero (διορθώθηκε προσωρινά στο `ee7e740`). Η είσοδος «Hero slides» της διαχείρισης είναι «σύντομα».

## Στόχος

Το marketing αλλάζει μόνο του τα slides του hero, με ημερομηνίες ανά slide, χωρίς ο hero να μένει ποτέ άδειος.

## Προσέγγιση

Δικός του επεξεργαστής στο `/admin/cms/slides`, αποθήκευση στο υπάρχον `CmsDocument` με πρόχειρο → δημοσίευση, ακριβώς
όπως οι σελίδες μαρκών (`lib/cms/brand-stores.ts`). **Χωρίς αλλαγή σχήματος βάσης.**

Απορρίφθηκαν: (B) ως component στις «Ζώνες σελίδων» — δύσχρηστο για λίστα πλούσιων slides· (C) νέος πίνακας `HeroSlide` —
θέλει db push και ξαναφτιαγμένο πρόχειρο/δημοσίευση.

## 1. Δεδομένα

`CmsDocument` με `collection = "hero.slides"`, `key = "home"`, `locale = "el"`:
- `data` = πρόχειρο, `published` = ό,τι διαβάζει η βιτρίνα, `publishedAt`, `version`, `updatedBy`.
- Σχήμα: `{ slides: HeroSlideDoc[] }` — η σειρά του πίνακα είναι η σειρά προβολής.

`HeroSlideDoc`:

| Πεδίο | Τύπος | Υποχρεωτικό | Σημείωση |
|---|---|---|---|
| `id` | string | ναι | σταθερό, παράγεται στη δημιουργία |
| `active` | boolean | ναι | διακόπτης |
| `from`, `to` | ISO string \| null | όχι | ώρα Ελλάδας· `to` μετά το `from` |
| `permanent` | boolean | ναι | εφεδρικό: εμφανίζεται όταν δεν υπάρχει άλλο ενεργό |
| `kicker` | string | όχι | μικρός τίτλος |
| `title` | string[1..3] | ναι | γραμμές του μεγάλου τίτλου |
| `body` | string | όχι | |
| `primary` | `{label, href}` | ναι | |
| `secondary` | `{label, href}` \| null | όχι | |
| `bullets` | string[0..3] | όχι | |
| `image` | `{url, alt}` | ναι | από τη βιβλιοθήκη πολυμέσων· `alt` υποχρεωτικό |
| `imageMobile` | `{url}` \| null | όχι | για οθόνες ≤ 767px |
| `video` | `{url}` \| null | όχι | mp4 χωρίς ήχο· η φωτογραφία μένει poster |
| `productId` | string \| null | όχι | cutout, σύνδεσμος και **τρέχουσα** τιμή από τον κατάλογο τη στιγμή της προβολής |

`href`: διαδρομή του site (`/…`) ή `https://…`. Επικύρωση σε κοινή συνάρτηση (server + φόρμα).

## 2. Βιτρίνα

`getHeroSlides()` (σήμερα επιστρέφει τα fixtures):
1. Διαβάζει το `published` (cache 60″, μηδενισμός στη δημοσίευση).
2. Κρατά όσα `active` και εντός `from/to` τη στιγμή του αιτήματος.
3. Αν δεν μείνει κανένα → τα `active && permanent`.
4. Αν δεν υπάρχει δημοσιευμένο έγγραφο → το `DEFAULT_HERO_DOC` του κώδικα (§4) περνά από τα ίδια βήματα 2–3, άρα χωρίς τα ληγμένα — ο hero δεν μένει ποτέ άδειος.
5. Για slide με `productId`: cutout (`cutoutFor`), σύνδεσμος `/proion/{slug}`, τιμή. Προϊόν που δεν υπάρχει/είναι ανενεργό → το slide προβάλλεται χωρίς προϊόν.

Η επιλογή (βήματα 2–3) είναι **καθαρή συνάρτηση** `pickSlides(doc, now)` για να ελέγχεται με tests.

`CinematicHero`: `<picture>` με `imageMobile` για ≤ 767px· ετικέτα τιμής δίπλα στο προϊόν. Ο τύπος `HeroSlide` αποκτά
`imageMobile?` και `price?`· η ζώνη `bento-hero` μένει μόνιμη (ήδη).

## 3. Διαχείριση — `/admin/cms/slides`

- Είσοδος «Hero slides» στο μενού χωρίς «σύντομα»· δικαίωμα `cms.slides.write` (το μόνο που υπάρχει) για προβολή και επεξεργασία.
- Λίστα καρτών slide: μικρογραφία, τίτλος, κατάσταση (**Ενεργό τώρα** / **Από 15/10** / **Έληξε 30/9** / **Μόνιμο** / **Ανενεργό**), πάνω/κάτω για σειρά, διαγραφή με επιβεβαίωση, «Νέο slide».
- Φόρμα ανά slide (ανοίγει στην κάρτα): όλα τα πεδία του §1 με ορατή εξήγηση· επιλογή φωτογραφίας/βίντεο από `MediaPickerDialog`, προϊόντος από τον υπάρχοντα `Picker` (kind "product").
- Ζωντανή προεπισκόπηση: το πραγματικό `CinematicHero` με το πρόχειρο, δίπλα στη φόρμα (στο κινητό από κάτω).
- Ενέργειες σελίδας: **Αποθήκευση πρόχειρου**, **Δημοσίευση**, **Επαναφορά στο δημοσιευμένο**, **Προεπισκόπηση στο site** (μόνο προσωπικό). Ένδειξη «Υπάρχουν αλλαγές που δεν έχουν δημοσιευτεί».
- Λάθη επικύρωσης δίπλα στο πεδίο· η δημοσίευση μπλοκάρεται με λάθη.
- Audit log για αποθήκευση/δημοσίευση/επαναφορά (όπως στις σελίδες μαρκών).
- Super adaptive 360px → desktop, χωρίς οριζόντια κύλιση, touch targets ≥ 44px, tokens `--fs-*`.

## 4. Μεταφορά

Τα 3 σημερινά slides γίνονται `DEFAULT_HERO_DOC` στον κώδικα (αντικαθιστά τα `heroSlides`). Καμία εγγραφή στη βάση σε GET: όσο δεν υπάρχει έγγραφο, η βιτρίνα δείχνει το `DEFAULT_HERO_DOC` και ο επεξεργαστής το φορτώνει ως αρχικό πρόχειρο· η πρώτη «Αποθήκευση» δημιουργεί το έγγραφο.
- «Καλοκαίρι 2026 · κλιματισμός» — `to` 2026-09-30 23:59 (ήδη ληγμένο)
- «Σεπτέμβριος · computing» — `to` 2026-09-30 23:59 (ήδη ληγμένο)
- «Euronics Renew» — `permanent: true`

Τα αρχεία (`/img/hero-*.jpg`, `/video/hero-clima.mp4`, cutouts) μένουν ως URL· νέα slides παίρνουν αρχεία από τη βιβλιοθήκη.

## 5. Έλεγχος

- `lib/cms/hero-slides.test.ts` (`npm test`): εντός/εκτός ημερομηνιών, μόνο `from` / μόνο `to`, ανενεργό, εφεδρεία στα μόνιμα, κανένα δημοσιευμένο → `DEFAULT_HERO_DOC` χωρίς τα ληγμένα, επικύρωση (`to < from`, κενός τίτλος, λάθος href).
- Browser: επεξεργαστής (δημιουργία, σειρά, δημοσίευση, επαναφορά), αρχική σε desktop και κινητό (φωτογραφία κινητού, προϊόν με τιμή), χωρίς οριζόντια κύλιση.

## Εκτός πεδίου

Πολλαπλές γλώσσες, A/B slides, προγραμματισμός ανά συσκευή/περιοχή, hero σε άλλες σελίδες εκτός της αρχικής.
